## 🎯 Top 10 Expected Viva Questions

### Q1: What is the core purpose of your chatbot?
**Answer:**
The chatbot provides **legal information for awareness purposes only** using Retrieval-Augmented Generation (RAG). It helps users understand legal concepts, laws, and their rights in simplified language. 

**Key Point:** The chatbot ONLY answers law-related questions. Non-legal queries are rejected before reaching the LLM using a dedicated law filter module.

---

### Q2: What is the "law-only validation" and why is it critical?
**Answer:**
The `law_filter.py` module acts as a gatekeeper to ensure only law-related queries are answered. It uses:

1. **Legal Keyword Detection** (100+ keywords)
   - Words: law, court, contract, rights, legal, Constitution, etc.
   - Patterns: Section 2, Article 14, IPC, etc.

2. **Non-Legal Keyword Exclusion** (80+ keywords)
   - Sports, movies, entertainment, personal advice, etc.

3. **Intent Classification**
   - Analyzes question patterns
   - Rejects vague/short queries without legal context

**Rejection Logic:**
```python
if non_legal_keywords_found AND no_legal_keywords:
    return REJECTION_MESSAGE
```

**Why Critical?** Without this, the LLM could answer ANY question, defeating the purpose of a "legal-only" chatbot.

---

### Q3: Explain the RAG (Retrieval-Augmented Generation) architecture.
**Answer:**
RAG has 5 stages:

```
1. User Query
   ↓
2. Law Filter (Validation)
   ↓
3. Retriever (Semantic Search)
   ├─ Generate query embedding
   ├─ Search vector database
   └─ Return top-K documents
   ↓
4. Context Augmentation
   ├─ Combine retrieved documents
   └─ Format as LLM context
   ↓
5. LLM Response + Disclaimer
```

**Why RAG?**
- Ensures factually accurate responses based on real legal documents
- Reduces LLM hallucinations
- Provides traceable sources
- Grounds answers in uploaded legal knowledge

### Q4: What are dense and sparse embeddings? How are they combined?
**Answer:**

**Dense Embeddings (70% weight):**
- Generated by Sentence Transformers (all-MiniLM-L6-v2)
- 384-dimensional vectors
- Captures semantic meaning
- Good for: Conceptual similarity

**Sparse Embeddings (30% weight):**
- Generated by BM25 algorithm
- Keyword-based matching
- Good for: Exact term matches, legal references

**Hybrid Search (Combination):**
```
combined_score = 0.7 × dense_score + 0.3 × sparse_score
```

**Why Both?**
- Dense: "right to education" matches "fundamental right to learn"
- Sparse: "Section 420" matches exact legal reference
- Together: Best retrieval accuracy

---

### Q5: Why use Pinecone? What's the alternative?
**Answer:**

**Pinecone:**
- Cloud-based vector database
- Fast retrieval (<500ms)
- Scalable to billions of vectors
- Managed service (no infrastructure)

**Alternative - LocalVectorStore:**
- In-memory storage using numpy
- Used for development/testing
- Automatically used if Pinecone fails
- Suitable for small datasets

**Selection Logic:**
```python
try:
    vector_store = PineconeVectorStore()
except:
    vector_store = LocalVectorStore()  # Fallback
```

**Why Pinecone in production?**
- Handles large documents
- Concurrent user queries
- Persistent storage
- Namespace organization

### Q6: How does the chatbot handle non-legal queries?
**Answer:**

**Process:**
```python
is_legal, reason = law_filter.is_legal_query(query)

if not is_legal:
    # LLM IS NOT CALLED
    return REJECTION_MESSAGE
```

**Rejection Message (Fixed):**
```
"I am designed to provide legal information only. 
Please ask questions related to law or legal awareness."
```

**Examples:**

✅ ACCEPTED:
- "What is my right to education?"
- "How do I file a case?"
- "What is IPC Section 302?"

❌ REJECTED:
- "Who won the cricket match?" (Sports)
- "How to cook biryani?" (Cooking)
- "Tell me about movies?" (Entertainment)

**Why Fixed Message?**
- Consistency
- Prevents LLM from being tricked
- Clear user communication

### Q7: What happens when documents are uploaded?
**Answer:**

**5-Stage Document Processing:**

1. **Validation** (pdf_processor.py)
   - Check file format (only .pdf)
   - Verify file readability
   - Extract metadata

2. **Text Extraction** (pdf_processor.py)
   - Use PyPDF2 to extract text
   - Preserve page structure
   - Handle multi-page documents

3. **Chunking** (chunker.py)
   - LangChain RecursiveCharacterTextSplitter
   - Chunk size: 500 characters
   - Overlap: 100 characters
   - Preserves semantic boundaries

4. **Embedding Generation** (embeddings.py)
   - Dense: Sentence Transformers (384-dim)
   - Sparse: BM25 tokenization
   - Batch processing for efficiency

5. **Storage** (vector_store.py)
   - Upload to Pinecone
   - Store local document references
   - Add metadata (source, type)

**Result:** Documents are searchable via semantic queries!

### Q8: What is the role of LLaMA via Groq API?
**Answer:**

**LLaMA 2 70B Model:**
- Open-source, powerful LLM
- Fast inference via Groq API
- Good for legal text understanding

**Integration Flow:**
```
Retrieved Legal Context + User Query
    ↓
[System Prompt] Define role & constraints
    ↓
[User Prompt] Context + Query + Instructions
    ↓
LLaMA 2 (via Groq)
    ↓
Generated Response
    ↓
[Append] Legal Disclaimer
    ↓
Display to User
```

**Parameters:**
- Temperature: 0.3 (Low = factual, not creative)
- Max tokens: 512 (Limit output length)
- Top-p: 0.95 (Diversity control)

**Why Groq?**
- Free tier (1000 requests/day)
- Fast API (2-5 sec responses)
- No need for expensive GPU
- High-quality LLaMA implementation

### Q9: How is the legal disclaimer ensured?
**Answer:**

**Disclaimer Text:**
```
"⚖️ **LEGAL DISCLAIMER**: This chatbot provides general legal 
information only and does not constitute legal advice. Please 
consult a qualified legal professional for specific cases."
```

**Enforcement:**
1. **Appended to Every Response**
   ```python
   response = llm_response + LEGAL_DISCLAIMER
   ```

2. **Validated Before Display**
   ```python
   response = ResponseValidator.ensure_disclaimer(response)
   ```

3. **Stored in config.py**
   - Cannot be removed by users
   - Cannot be overridden by LLM

**Why Critical?**
- Legal liability protection
- User expectation management
- Ethical responsibility
- Regulatory compliance
